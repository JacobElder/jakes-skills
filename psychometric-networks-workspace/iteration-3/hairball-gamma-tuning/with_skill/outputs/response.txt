91 out of 105 edges (87% density) is pathologically dense — a hairball, as you say — and it's a clear signal that something upstream is wrong before you even get to interpretation. This isn't a rendering problem; it means the model is finding that almost every item is conditionally associated with almost every other after controlling for all remaining items, which is almost never substantively true. Three culprits, roughly in order of suspicion:

---

## Culprit 1: Node redundancy (check this first)

Depression scales are the canonical case. Items like "sad mood," "depressed affect," and "feels empty" have nearly identical conditioning sets — every other item predicts them equally well — so they produce near-identical columns in the partial-correlation matrix. This creates a cluster of very strong edges that then propagates spurious density throughout the graph.

Run `goldbricker` before anything else:

```r
library(networktools)
gb <- goldbricker(data, threshold = 0.25, corMethod = "cor_auto")
print(gb)
```

`goldbricker` flags pairs whose partial-correlation profiles are so similar that they likely represent redundant nodes. Any pair flagged at `threshold = 0.25` should be either dropped or combined into a composite before re-estimation. If you have a 15-item scale with several near-synonym items, this alone can collapse density dramatically.

---

## Culprit 2: Gamma is too liberal — increase it

The EBIC tuning parameter `gamma` controls how aggressively the model penalizes edge inclusion. The default of `0.5` is fine for many settings but can be too liberal for (a) highly correlated item sets and (b) samples below ~300. Try stepping up:

```r
# Your current (probably implicit) gamma = 0.5
net_0.5 <- estimateNetwork(data, default = "EBICglasso",
                           corMethod = "cor_auto", tuning = 0.5)

# More conservative
net_1.0 <- estimateNetwork(data, default = "EBICglasso",
                           corMethod = "cor_auto", tuning = 1.0)

# Check what lambda was selected — if it's near 0, regularization is minimal
net_0.5$results$optLambda
net_1.0$results$optLambda
```

If `optLambda` for your current model is very small (close to the minimum of the lambda path), that's a sign the EBIC criterion itself is selecting almost no regularization — the data are so correlated that the penalized likelihood keeps preferring denser models. Higher gamma shifts the tradeoff toward parsimony. There's no single "correct" value; `gamma = 0.5` is the field default per Epskamp & Fried (2018), but for very correlated item sets values of 0.75–1.0 are defensible and commonly used.

---

## Culprit 3: The conceptual problem — GGM on a unidimensional scale

This is the deepest issue. If your 15 items are all from a single depression scale designed to measure one construct (PHQ-9, BDI-II, CESD, etc.), then the GGM is being asked: *"What are the pairwise conditional associations among items that all reflect the same underlying thing?"* The answer will always be "almost everything connects to everything," because after you partial out the other 14 items, most pairs still share variance they can't fully account for through the other nodes.

This is not a bug in `bootnet` — it's the GGM faithfully representing that the item set is nearly unidimensional. The network approach gains traction on **heterogeneous** node sets (e.g., depression symptoms + anxiety symptoms + somatic complaints + functional impairment) where there are real conditional independencies to find.

Diagnostic: run a quick factor analysis.

```r
library(psych)
fa.parallel(data, fm = "ml", fa = "fa")
```

If scree/MAP says 1 factor, a GGM on this set will be dense no matter what. That doesn't mean network analysis is wrong to apply, but it means you need to either (a) expand the node set to include conceptually distinct variables, or (b) accept that the network's edges are mostly capturing item-level heterogeneity within a single construct and interpret accordingly.

---

## Immediate action plan

```r
library(bootnet); library(qgraph); library(networktools)

# Step 1: Check raw inter-item correlations
cors <- cor_auto(data)
hist(cors[upper.tri(cors)], main = "Inter-item correlations", xlab = "r")
# If the distribution is centered > 0.4, you're in near-unidimensional territory

# Step 2: Flag redundant nodes
gb <- goldbricker(data, threshold = 0.25, corMethod = "cor_auto")
print(gb)

# Step 3: Re-estimate after pruning redundant items, with higher gamma
data_pruned <- data[, !names(data) %in% gb$suggested_reductions$to_remove]
net <- estimateNetwork(data_pruned, default = "EBICglasso",
                       corMethod = "cor_auto", tuning = 1.0)
plot(net, layout = "spring", theme = "colorblind")

# Step 4: If still dense, try TMFG as a ceiling — forces planar graph
# (max 3*(n-2) edges, so for 15 nodes: max 39 edges)
net_tmfg <- estimateNetwork(data_pruned, default = "TMFG", corMethod = "cor_auto")
plot(net_tmfg, layout = "spring", theme = "colorblind")
```

## One thing not to do

Don't tune `gamma` upward until you get a "nice-looking" sparse graph and then report the result as if it were a default analysis. If you do increase gamma, justify the choice (e.g., "given the high inter-item correlations and moderate N, we used gamma = 1.0 to avoid overfitting" with citation to Epskamp & Fried 2018 discussing the tradeoff) and report the number of edges under both gamma = 0.5 and gamma = 1.0 as a sensitivity check. Reviewers who know this literature will ask.

With N = 210 and 15 nodes, your CS-coefficients for centrality are also likely to be marginal — run the case-dropping bootstrap and report them before interpreting any centrality results.
