# Network Analysis of Depression Symptoms in R

With 21 ordinal items (0–4) and N=412, you have a well-powered setup for a regularized Gaussian Graphical Model (GGM). The key methodological decision is that **you must not treat Likert responses as continuous** — we'll use polychoric correlations under the hood. Here's the full pipeline.

---

## 1. Install & Load Packages

```r
install.packages(c("bootnet", "qgraph", "networktools", "psych", "ggplot2", "dplyr"))

library(bootnet)       # network estimation + bootstrapping
library(qgraph)        # visualization + EBICglasso
library(networktools)  # bridge centrality, goldbricker
library(psych)         # polychoric, describe
library(ggplot2)
library(dplyr)
```

---

## 2. Data Inspection

```r
# Assume your data frame is `dat`, columns = item variables only
# Remove any non-item columns first:
# dat <- df %>% select(PHQ1:item21)

# --- Structure check ---
str(dat)
dim(dat)  # Should be 412 x 21

# --- Missing data ---
colSums(is.na(dat))
mean(is.na(dat))  # Ideally < 5%

# If missingness is low (< 5%), listwise deletion is defensible.
# For more missingness, use Bayesian imputation (mice package).
dat_clean <- na.omit(dat)

# --- Marginal distributions ---
# All items should use most of the 0-4 range; watch for zero-variance items
psych::describe(dat_clean)
```

**Red flags to catch here:**
- Any item where >80% of responses are a single value (near-zero variance → consider dropping)
- Extreme skew on any item (not fatal, but polychoric handles it better than Pearson)

---

## 3. Estimate the Network

Use `bootnet::estimateNetwork()` with `cor_auto`, which automatically detects ordinal variables (≤7 ordered categories) and computes **polychoric correlations**, then applies **EBICglasso** regularization.

```r
# Label your nodes clearly — these appear in figures
node_labels <- c(
  "Anhedonia", "Low mood", "Sleep", "Fatigue", "Appetite",
  "Guilt", "Concentration", "Psychomotor", "Suicidal",
  # ... your 12 additional items:
  "Item10", "Item11", "Item12", "Item13", "Item14",
  "Item15", "Item16", "Item17", "Item18", "Item19", "Item20", "Item21"
)

# --- Core estimation ---
net <- estimateNetwork(
  dat_clean,
  default     = "EBICglasso",  # regularized partial correlations
  corMethod   = "cor_auto",    # polychoric for ordinal items
  tuning      = 0.5,           # EBIC gamma; 0.5 is standard, higher = sparser
  verbose     = TRUE
)

# Inspect the estimated edge weight matrix
net$graph  # 21x21 matrix of partial correlations (zeros = regularized away)
sum(net$graph != 0) / 2  # number of retained edges
```

**On the tuning parameter γ:**
| γ value | Effect |
|---|---|
| 0.25 | More edges retained, higher false-positive risk |
| 0.50 | Standard; good balance (use this by default) |
| 0.50+ | Sparser; reduces false positives in small N |

Since N=412 is moderate, γ=0.5 is appropriate.

## 5. Centrality Analysis

Centrality tells you which symptoms are most "influential" in the network. Three indices matter:

| Index | Interpretation |
|---|---|
| **Strength** | Sum of absolute edge weights; overall connectedness |
| **Betweenness** | How often a node lies on shortest paths between others |
| **Closeness** | How quickly a node can reach all others |

```r
# --- Compute & plot centrality ---
centralityPlot(net,
               include   = c("Strength", "Betweenness", "Closeness"),
               labels    = node_labels,
               orderBy   = "Strength")
```

```r
# --- Extract raw values ---
cent <- centrality_auto(net)
cent$node.centrality %>%
  mutate(Node = node_labels) %>%
  arrange(desc(Strength))
```

> **Interpretation note:** In cross-sectional data, centrality indices should be treated as descriptive, not causal. High-strength nodes are candidates for therapeutic targets, but longitudinal or experimental data are needed to confirm this.

## 6. Bootstrap Stability Analysis

This is **non-optional** for publishable work. You need to assess:
1. **Edge weight accuracy** — how wide are the CIs around each edge?
2. **Centrality stability** — do centrality rankings hold if you drop cases?

```r
# --- 6a. Nonparametric bootstrap (edge weight CIs) ---
# n = 1000 is publication standard; start with 500 to check runtime
boot1 <- bootnet(net,
                 nBoots     = 1000,
                 nCores     = 4,        # adjust to your machine
                 statistics = c("edge", "strength", "betweenness", "closeness"))

# Plot edge weight CIs (sorted by weight)
plot(boot1, 
     labels  = FALSE,
     order   = "sample")

# Significance: edges whose CI excludes zero are robust
plot(boot1,
     plot       = "difference",
     onlyNonZero = TRUE,
     order      = "sample")
```

```r
# --- 6b. Case-dropping subset bootstrap (centrality stability) ---
boot2 <- bootnet(net,
                 nBoots        = 1000,
                 type          = "case",
                 nCores        = 4,
                 statistics    = c("strength", "betweenness", "closeness"))

# CS-coefficient: should be >= 0.25; ideally >= 0.50
corStability(boot2)
```

**Interpreting CS-coefficients:**
- ≥ 0.50: Centrality order is stable — report with confidence
- 0.25–0.50: Moderate stability — report with caveats
- < 0.25: Unstable — do not interpret centrality rankings

## 7. Check for Redundant Nodes (Goldbricker)

Items that share >50% of their variance with another item (e.g., two near-identical sleep items) can artificially inflate edges. Check before finalizing.

```r
goldbricker(dat_clean,
            p          = 0.05,
            method     = "hittner2003",
            threshold  = 0.25,
            corMin     = 0.50)
```

If flagged pairs are found, consider averaging the two items, dropping one, or modeling them as a single node.

```
dat_clean
  └─ estimateNetwork(default="EBICglasso", corMethod="cor_auto")  ← polychoric + regularization
        ├─ plot()                    ← spring layout visualization
        ├─ centralityPlot()          ← strength / betweenness / closeness
        ├─ bootnet(type="nonpar")    ← edge weight CIs
        └─ bootnet(type="case")      ← CS-coefficient for centrality stability
```
