91/105 edges is a red flag — EBICglasso is *supposed* to produce sparse networks. Something is pushing regularization toward near-zero, and there are several likely culprits. Let me walk through diagnosis and fixes.

---

## Why This Happens: The Usual Suspects

### 1. Strong common factor structure (most likely root cause)

Depression scales (PHQ-9, BDI, CES-D, etc.) are explicitly designed to be highly intercorrelated — they're measuring one strong latent factor. With Cronbach's α typically .85–.92, the items are so collinear that even *after* partialling out neighbors, substantial residual associations survive regularization. GLASSO can't zero them out because they're genuinely non-zero partial correlations under a strong-factor structure. This is a fundamental tension in network psychometrics, not a bug in your code.

### 2. γ tuning parameter too low

The EBIC hyperparameter γ controls the complexity penalty. The bootnet default is `tuning = 0.5`, but if you're using `gamma = 0` (which reduces to standard BIC), you get *much* denser networks. Check what you actually ran:

```r
# What you likely ran:
net <- estimateNetwork(data, default = "EBICglasso")
# Default tuning = 0.5 — but double-check:
net$arguments$tuning
```

### 3. Pearson correlations on ordinal data

If your depression items are Likert-scale (0–3, 0–4, etc.) and you used Pearson correlations, the input matrix is misspecified. Polychoric correlations are the correct input for ordinal items and often produce meaningfully different (sparser) networks.

### 4. Small N relative to item intercorrelations

N=210 with 15 nodes is a ratio of 14:1 — acceptable by conventional standards, but when items are near-perfectly intercorrelated, the precision matrix becomes ill-conditioned and regularization struggles to find a sparse optimum.

## Diagnostic Steps

**Step 1: Check your correlation matrix**
```r
library(qgraph)
R <- cor_auto(data)  # auto-detects ordinal, uses polychoric
corrplot::corrplot(R, order = "hclust")
```
If almost every cell is > .40, you have a strong-factor problem.

**Step 2: Inspect the regularization path**
```r
library(qgraph)
EBICpath <- EBICtune(R, n = 210, gamma = 0.5)
plot(EBICpath)  # Where is EBIC minimized? 
```
If the minimum is at near-zero λ (far right of path), EBIC prefers a dense network regardless of tuning.

**Step 3: Check dimensionality**
```r
library(psych)
fa.parallel(data, fm = "ml")
VSS(data, n = 8, fm = "ml")
```
A strongly unidimensional scale will produce a hairball. Networks are most interpretable for multidimensional constructs.

---

## Fixes, Ranked by Impact

### Fix 1: Use `cor_auto` for polychoric correlations
```r
net <- estimateNetwork(
  data,
  default    = "EBICglasso",
  corMethod  = "cor_auto",   # polychoric for ordinal items
  tuning     = 0.5
)
```
This alone often reduces edge count substantially for Likert data.

### Fix 2: Increase γ
Higher γ = stronger penalty for complexity = sparser network. Compare across a grid:

```r
nets <- lapply(c(0.25, 0.50, 0.75, 1.0), function(g) {
  estimateNetwork(data, default = "EBICglasso", 
                  corMethod = "cor_auto", tuning = g)
})
sapply(nets, function(n) sum(n$graph != 0) / 2)  # edge counts
```

γ = 0.5 is conventional but not sacred. Values up to 1.0 have been used in published work when the sample size warrants it. *Do report whichever γ you choose and why.*

### Fix 3: Switch to TMFG as a comparison estimator
TMFG (Triangulated Maximally Filtered Graph) always produces exactly 3(N−2) = 39 edges for 15 nodes — it's structurally sparse by construction and makes no assumptions about EBIC:

```r
net_tmfg <- estimateNetwork(data, default = "TMFG", 
                             corMethod = "cor_auto")
plot(net_tmfg)
```
It's a useful sanity check: if TMFG looks substantively interpretable and EBICglasso is a hairball, that's strong evidence your regularization is misconfigured.

### Fix 4: `ggmModSelect` (stepwise, often sparser)
```r
net_ggm <- estimateNetwork(data, default = "ggmModSelect",
                           corMethod = "cor_auto")
```
Uses stepwise model comparison rather than regularization. Can produce much sparser networks from the same data.

### Fix 5: Consider whether network analysis is the right tool

If the parallel analysis shows 1 clear factor and the scree plot drops sharply after factor 1, your 15 items are better described by a *reflective latent variable model* than a network. This isn't failure — it's what the data support. A dense EBICglasso network from a unidimensional scale is a known artifact:

> van Bork et al. (2019, *Psychological Methods*): "When the true model is a common factor model, network models will produce dense, highly interconnected graphs."

---

## Quick Reference: What to Report

Whatever you settle on, report:
- Estimator (EBICglasso vs. TMFG vs. ggmModSelect)
- γ tuning value
- Correlation type (Pearson vs. polychoric)
- Edge count and network density
- Bootstrap stability (CS-coefficient ≥ 0.25 minimum, ≥ 0.50 preferred)

```r
# Bootstrap stability — run after you have a clean network
boot <- bootnet(net, nBoots = 1000, type = "case")
plot(boot, statistics = "strength")
corStability(boot)
```

---

**Bottom line:** Start with `corMethod = "cor_auto"` and γ = 0.5, run TMFG as a comparison, and run a factor analysis to understand your data's dimensionality. If you genuinely have a near-unidimensional scale, the network literature's honest answer is that EBICglasso will struggle — and you should say so.
