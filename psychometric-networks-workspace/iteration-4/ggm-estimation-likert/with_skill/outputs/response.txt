## Psychometric network analysis: 21-item depression scale, N = 412

Your setup is the canonical GGM use case. Here's the full pipeline in order — estimation, visualization, centrality, accuracy/stability, and then some item-level caveats worth knowing before you interpret anything.

---

### Step 0 — Install and load packages

```r
install.packages(c("bootnet", "qgraph", "networktools", "psychonetrics"))
# If IsingFit/mgm needed later, add those; not needed here.

library(bootnet)
library(qgraph)
library(networktools)
```

`bootnet` loads `qgraph` as a dependency, but load it explicitly so you can call plotting functions directly.

---

### Step 1 — Check for node redundancy *before* estimating

This is the step most tutorials skip, and it matters here because you have 12 custom items alongside PHQ-9 items that likely overlap thematically (e.g., if you have both "felt sad" and "felt depressed" as separate items, they'll produce a spuriously strong edge and inflate each other's centrality).

```r
# Assuming your data frame is called `dat` with 21 columns, one per item.

goldbricker(
  dat,
  p      = 0.05,        # significance threshold for proportion test
  method = "hittner2003",
  threshold = 0.25,     # flag pairs where > 25% of partials are non-sig different
  corMin  = 0.50        # only consider pairs with r >= .50 to start
)
```

`goldbricker` compares each item pair's partial-correlation profiles. Items flagged as "redundant" are near-duplicates — their conditioning sets are too similar for the graphical lasso to tell them apart cleanly. If any pairs are flagged, your options are: (a) drop one item on theoretical grounds, (b) combine into a composite, or (c) proceed anyway but caveat the interpretation of those edges. **Decide this before estimating** — changing nodes after you see the network is p-hacking the graph structure.

---

### Step 2 — Estimate the network

```r
net <- estimateNetwork(
  dat,
  default    = "EBICglasso",
  corMethod  = "cor_auto",   # key: detects ordinal vars → polychoric correlations
  tuning     = 0.5,          # EBIC gamma; 0.5 is the field default
  refit      = TRUE          # refit without regularization penalty on retained edges
)
```

**Why `cor_auto` matters**: your items are 0–4 ordered integers. `cor_auto` (from the `qgraph` package) recognizes them as ordinal and computes **polychoric correlations** via `lavaan` before passing them to the graphical lasso. If you use Pearson correlations on Likert data, you'll systematically attenuate edge weights, particularly for skewed items like suicidality.

**What `refit = TRUE` does**: the graphical lasso shrinks all edges, including retained ones. Refitting OLS on just the non-zero edges removes that shrinkage bias from your final edge weights. This is recommended for interpretation.

**Tuning parameter**: `0.5` is the Epskamp & Fried (2018) default. If you want to see whether your key findings are robust to this choice, re-run at `0.25` (more liberal, denser graph) and `1.0` (more conservative, sparser) and confirm that the edges you're interpreting survive across values.

### Step 3 — Plot the network

```r
# Store the layout so all subsequent plots use the same node positions
L <- averageLayout(net)

plot(
  net,
  layout      = L,
  theme       = "colorblind",
  labels      = names(dat),        # your item names/abbreviations
  label.scale = TRUE,
  edge.labels = FALSE,             # set TRUE if you want edge weights shown
  title       = "Depression symptom network (EBICglasso, γ = 0.5)"
)
```

Conventions:
- **Green edges** = positive partial correlations (symptoms activate each other)
- **Red edges** = negative partial correlations (rare in depression networks; check if they appear whether they make theoretical sense)
- **Edge thickness** = edge weight magnitude
- Isolated nodes (no edges) mean the graphical lasso zeroed out all connections for that item — it's not "unrelated", it's just that its associations are fully explained by other items in the set

Save `L` and reuse it for every plot in the paper so node positions are consistent across figures.

---

### Step 4 — Centrality

```r
centralityPlot(
  net,
  include = c("Strength", "ExpectedInfluence"),
  orderBy = "ExpectedInfluence"
)
```

**Use Expected Influence, not Strength, as your primary index.** Strength sums *absolute* edge weights, so a node with one strong negative edge and one strong positive edge looks "central" the same as a node with two strong positive edges — which is misleading for symptoms. Expected Influence (Robinaugh et al., 2016) sums signed weights, so sign information is preserved.

**Do not report closeness or betweenness.** These indices are designed for flow/distance problems on sparse unweighted graphs and are systematically unreliable in dense weighted partial-correlation networks (Bringmann et al., 2019). If reviewers ask, cite that paper and the stability results you'll generate in Step 5.

```r
# Get the numeric centrality table if you need values for a table
centralityTable(net) |>
  dplyr::filter(measure %in% c("Strength", "ExpectedInfluence"))
```

### Step 5 — Accuracy and stability (non-negotiable)

#### 5a. Bootstrapped edge-weight CIs

```r
boot_nonparam <- bootnet(
  net,
  nBoots = 1000,
  type   = "nonparametric",
  nCores = parallel::detectCores() - 1   # parallelise; drop this if on Windows
)

plot(boot_nonparam, labels = FALSE, order = "sample")
```

This shows each edge's bootstrapped 95% CI around its sample estimate. Wide, overlapping CIs are normal — it means you should trust the **ordering** of edges more than their absolute magnitudes. Use the difference test (below) rather than eyeballing CI overlap.

```r
# Bootstrapped difference test: which pairs of edges are distinguishable?
plot(boot_nonparam, "edge", plot = "difference", onlyNonZero = TRUE, order = "sample")
```

#### 5b. Centrality stability — CS-coefficient

```r
boot_case <- bootnet(
  net,
  nBoots = 1000,
  type   = "case",
  statistics = c("Strength", "ExpectedInfluence"),
  nCores = parallel::detectCores() - 1
)

corStability(boot_case)
```

`corStability()` returns the **CS-coefficient**: the maximum fraction of cases you can drop while keeping centrality rankings correlated ≥ 0.7 with the full-sample ranking at 95% probability.

| CS-coefficient | Interpretation |
|---|---|
| ≥ 0.50 | Acceptable — interpret centrality with reasonable confidence |
| 0.25 – 0.49 | Minimum threshold — note instability in text |
| < 0.25 | **Do not interpret centrality** |

With N = 412 and 21 items, Strength typically comes in around 0.4–0.6 in published work. Expected Influence is often slightly lower. If your CS is below 0.25, the story to tell is the edge structure, not centrality ranking.

```r
# Plot how centrality correlations degrade as cases are dropped
plot(boot_case, statistics = c("Strength", "ExpectedInfluence"))
```

#### 5c. Centrality difference test

```r
plot(boot_nonparam, "centrality", plot = "difference",
     statistics = c("Strength", "ExpectedInfluence"))
```

In most published networks, **very few pairwise centrality comparisons are actually distinguishable** — this is the norm, not a failure. It means you should describe the overall centrality pattern (e.g., "sleep disturbance and depressed mood showed the highest Expected Influence") rather than claiming precise rankings.

### Step 6 — Bridge centrality (if you have theoretical communities)

If your 21 items include theoretically meaningful clusters (e.g., PHQ-9 somatic items vs. cognitive items vs. your 12 additional items), bridge centrality tells you which nodes most strongly connect the communities:

```r
# Define communities as a named vector matching your node order
communities <- c(
  rep("PHQ9", 9),
  rep("Additional", 12)
)

bridge_results <- bridge(net, communities = communities)
plot(bridge_results)
```

Bridge nodes are candidates for cross-construct connectors — useful if you're arguing your additional items tap something the PHQ-9 misses.

### Things to watch for with this specific dataset

1. **PHQ-9 item 9 (suicidality)** is typically skewed hard toward zero in community samples. Polychoric handles the skew better than Pearson, but the item may still end up isolated or with weak edges — that's a feature of the data, not a bug, but worth commenting on.

2. **12 custom items + 9 PHQ items**: make explicit in the paper why those 12 were chosen. Node selection is a theoretical commitment — a reviewer will ask whether the additional items change the PHQ-9 subgraph, which they will.

3. **N = 412 with 21 nodes** is workable but not large. Expect moderately wide bootstrap CIs and a CS-coefficient that may fall in the 0.25–0.50 range for some indices. Be conservative about strong centrality claims.

4. **Cross-sectional causal limit**: a high-centrality node is not demonstrated to be a good intervention target. Centrality is descriptive of the estimated graph under this sample and these items — not a causal model.

The canonical tutorial to cite is **Epskamp, Borsboom & Fried (2018)** in *Behavior Research Methods* — it's freely available and covers all of the above in one paper.
