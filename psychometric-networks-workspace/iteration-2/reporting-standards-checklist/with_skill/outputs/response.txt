## Methods section

### Data and nodes
- **Node selection rationale** — don't just say "we used the [scale name]"; justify *why* these 12 items constitute the right node set for your research question. Reviewers increasingly flag under-justified node choices as a theoretical weakness.
- **Node redundancy check** — run `networktools::goldbricker(data)` and report whether any item pairs had nearly identical partial-correlation profiles. Near-duplicate items (e.g., "nervous" and "anxious") produce spuriously strong edges and inflate those nodes' centrality. If you pruned or combined items, say so and why.
- **Sample size** — N=340 for 12 nodes is workable but not generous; be explicit and note the implications for stability (reviewers will check your CS-coefficients against this).

### Estimation
State all of the following explicitly:
- **Model**: Gaussian Graphical Model (GGM)
- **Estimator**: graphical LASSO (GLASSO) with EBIC model selection
- **Tuning parameter**: gamma = 0.5 (and note this is the field default, cite Epskamp & Fried, 2018)
- **Correlation type**: polychoric (because items are ordinal), estimated via `cor_auto` in `qgraph`/`bootnet` — specify this; reviewers want to know you didn't use Pearson on Likert data
- **Software**: `bootnet` version X, `qgraph` version X, R version X

A one-sentence template:
> "We estimated a GGM using the graphical LASSO with EBIC model selection (gamma = 0.5; Epskamp & Fried, 2018) on polychoric correlations (estimated via `cor_auto`; Epskamp et al., 2018) using the `bootnet` package (v[X]; Epskamp et al., 2018) in R (v[X])."

### Accuracy and stability plan
Pre-state that you will (a) bootstrap edge-weight CIs, (b) run a case-dropping stability analysis, and (c) report CS-coefficients. Reviewers increasingly want this flagged in methods, not buried in a supplement.

## Results section

### 1. The network plot
- Spring layout (`layout = "spring"`, i.e., Fruchterman-Reingold) — state the layout algorithm
- Color-blind safe theme (`theme = "colorblind"` in `qgraph`)
- Green = positive edges, red = negative edges; thicker/darker = stronger weight — include a legend or describe the encoding in the caption

### 2. Edge-weight table
Provide the full partial-correlation matrix (or at minimum the non-zero edges) as a table or supplement. Readers need to verify and reuse your results.

### 3. Bootstrapped edge-weight CIs — the accuracy check
```r
boot_nonpar <- bootnet(net, nBoots = 1000, type = "nonparametric")
plot(boot_nonpar, labels = FALSE, order = "sample")
```
- Report the bootstrapped CI plot (edge weights ± CI)
- Run and report the **bootstrapped difference test** for the edges you specifically interpret or compare: `plot(boot_nonpar, "edge", plot = "difference")`
- **Critical caveat to include**: non-overlapping CIs ≠ a statistically distinguishable difference; the difference test is required for any claim that edge A is stronger than edge B

### 4. Centrality — report only what's defensible
For a GGM of anxiety symptoms, report:
- **Strength** (sum of absolute edge weights) as the primary index
- **Expected Influence** as an alternative/supplement — particularly important if any edges are negative (which anxiety symptom networks often have, e.g., avoidance ↔ somatic items), because Strength sums *absolute* values and masks sign. Robinaugh et al. (2016) is the citation.
- **Do not report Closeness or Betweenness** — drop them if your current draft includes them. Bringmann et al. (2019, *J Abnormal Psychol*) established that these indices are unreliable and theoretically ill-suited to dense weighted partial-correlation graphs.

### 5. CS-coefficients — the stability check
```r
boot_case <- bootnet(net, nBoots = 1000, type = "case",
                     statistics = c("strength", "expectedInfluence"))
corStability(boot_case)
plot(boot_case, statistics = c("strength", "expectedInfluence"))
```
Report the CS-coefficient for each centrality index you interpret. The thresholds are:
| CS-coefficient | Interpretation |
|---|---|
| ≥ 0.50 | Acceptable to interpret |
| 0.25 – 0.49 | Interpret with caution, note limitation |
| < 0.25 | **Do not interpret centrality** |

With N=340 and 12 nodes you will likely land in the acceptable range for Strength, but you must check and report the actual number.

### 6. Centrality difference tests
```r
plot(boot_nonpar, "strength", plot = "difference")
```
Report which node pairs are actually distinguishable. Resist ranking all nodes 1–12 by centrality without noting which adjacent ranks are statistically indistinguishable.

### 7. Causal/interpretive limitations
Every cross-sectional network paper now needs an explicit statement that:
- The GGM is a descriptive statistical model of conditional associations, not a causal model
- High-centrality nodes are not necessarily optimal intervention targets — that claim requires either experimental or longitudinal evidence the current design cannot supply
- Cross-sectional networks are not temporal networks; you cannot infer which symptoms *drive* others

## What likely triggered the reviewer criticism

The most common gaps in cross-sectional network write-ups are:

1. Missing or underpowered stability checks (no CS-coefficients, or CS < 0.25 with centrality still interpreted)
2. Reporting betweenness/closeness without acknowledging Bringmann et al. (2019)
3. Comparing edge weights or centrality ranks without the bootstrapped difference test
4. Omitting the edge-weight table or supplement
5. Overclaiming causality ("symptom X drives symptom Y") from a cross-sectional GGM
6. Not checking for node redundancy

Run through these six and you'll likely satisfy a methodology-aware reviewer. For the authoritative version, the Burger et al. (2023) paper is open access in *Psychological Methods* — include it in your references and consider citing it directly in your methods section as the reporting framework you followed.
