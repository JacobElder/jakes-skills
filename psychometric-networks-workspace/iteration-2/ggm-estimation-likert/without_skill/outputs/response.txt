## 3. Network Estimation

### 3a. The Core Decision: Estimator

Your data are **ordinal** (0–4 Likert). The two main paths:

| Approach | When to use | How |
|---|---|---|
| **EBICglasso on polychoric correlations** | Most published psych network papers; fast; defensible | `cor_auto()` + `EBICglasso` |
| **Ordinal GGM via `psychonetrics`** | More statistically principled for ordinal data; slower | `ggm()` with ordinal estimation |

Start with the first (it's the field standard and easiest to interpret), then optionally validate with the second.

### 3b. EBICglasso — the workhorse

```r
# bootnet::estimateNetwork handles the full pipeline
# cor_auto() (inside qgraph) auto-detects ordinal variables
# and computes polychoric correlations — critical for your data

net <- estimateNetwork(
  data        = df_complete,
  default     = "EBICglasso",   # regularized partial correlations
  corMethod   = "cor_auto",     # polychoric for ordinal items
  tuning      = 0.5,            # EBIC hyperparameter γ; 0.5 is standard
  verbose     = TRUE
)

# Inspect the estimated edge weights (partial correlations)
net$graph          # 21 x 21 matrix; zero = no edge (regularized out)
sum(net$graph != 0) / 2   # number of unique edges retained
```

**Tuning parameter γ:** The default `0.5` penalizes model complexity, favouring sparser networks. If you want to check sensitivity, re-run with `tuning = 0.25` (more edges) and `tuning = 1.0` (fewer edges). If major edges disappear under small changes, interpret with caution.

### 3c. (Optional) Non-regularized alternative

Regularization can introduce false negatives. An increasingly popular check is to also run the unregularized `ggmModSelect`:

```r
net_mg <- estimateNetwork(
  data      = df_complete,
  default   = "ggmModSelect",
  corMethod = "cor_auto"
)
```

Compare the two networks — edges present in both are the most trustworthy.

## 5. Centrality Indices

```r
# Three standard indices
centralityPlot(
  net,
  include  = c("Strength", "Closeness", "Betweenness"),
  orderBy  = "Strength"
)

# Extract raw values
ci <- centrality_auto(net)
ci$node.centrality
```

**Which index to trust:**

- **Strength** (sum of absolute edge weights): most stable, prefer this for substantive interpretation
- **Betweenness / Closeness**: notoriously unstable in small-to-moderate samples; treat as exploratory
- **Expected Influence**: better than strength when you care about edge sign (positive vs. negative); compute via `networktools`

```r
# Expected Influence (accounts for edge direction/sign)
ei <- expectedInf(net$graph)
plot(ei, order = "value", zscore = TRUE)
```

## 6. Stability & Accuracy Bootstrapping — Do Not Skip This

With N = 412 and 21 nodes (210 possible edges), stability checks are essential. Two separate bootstraps are needed.

### 6a. Edge weight accuracy (nonparametric bootstrap)

```r
# Resample cases with replacement; re-estimate the network each time
# n = 1000 is standard; this will take a few minutes
set.seed(42)
boot_nonpar <- bootnet(
  net,
  nBoots       = 1000,
  type         = "nonparametric",
  nCores       = 4    # parallel processing; adjust to your machine
)

# Plot edge weight CIs
plot(boot_nonpar,
     labels  = FALSE,
     order   = "sample")

# Test whether pairs of edges differ significantly
# (helps avoid over-interpreting small differences in centrality)
differenceTest(boot_nonpar, it1 = "It1", it2 = "It2",   # replace with real names
               measure = "strength")
```

### 6b. Centrality stability (case-dropping bootstrap)

```r
set.seed(42)
boot_case <- bootnet(
  net,
  nBoots       = 1000,
  type         = "case",
  statistics   = c("strength", "closeness", "betweenness", "expectedInfluence"),
  nCores       = 4
)

# CS-coefficient: correlation between full-sample and subset centrality
# Rule of thumb: CS > 0.5 = stable; 0.25–0.5 = interpret cautiously; < 0.25 = unreliable
corStability(boot_case)

# Visualise stability
plot(boot_case, statistics = c("strength", "closeness", "betweenness"))
```

**Typical finding:** Strength is usually stable (CS > 0.5). Betweenness and closeness often fall below 0.25 in samples this size — if that happens, do not rank nodes by those measures.

## 7. Optional but Useful Extras

### 7a. Bridge centrality (if your symptom clusters are theoretically distinct)

```r
# Measures how much a node connects different communities
communities <- list(
  A = 1:9,    # PHQ-9

bridge_ci <- bridge(net$graph,
                    communities = communities,
                    useCommunities = "all")
```

### 7b. Goldbricker — detect redundant nodes

```r

```

## 8. Reporting Checklist

When writing up:

- [ ] Report the estimator (EBICglasso), correlation method (polychoric via `cor_auto`), and γ tuning parameter
- [ ] Report N, number of nodes, and number of edges retained vs. possible
- [ ] Report CS-coefficients for each centrality index and note which ones are stable
- [ ] Include the bootstrap edge-weight CI plot (or at minimum note the bootstrap was run)
- [ ] Note the cross-sectional limitation explicitly: these edges are **conditional associations**, not causal pathways — the "network as a causal system" interpretation requires longitudinal or experimental data

## Quick Caveat on Cross-Sectional Networks

The field has an ongoing debate about what cross-sectional GGMs actually capture. With N = 412 you're in reasonable shape for edge detection, but:

1. **Edges ≠ causal links.** A large Anhedonia–Depressed Mood edge just means they're strongly associated after conditioning on other symptoms.
2. **Reproducibility varies** across samples; the stability bootstrap addresses within-sample stability, not cross-sample generalizability.
3. **Temporal dynamics** (why Borsboom's network theory is compelling) require ESM/EMA data — flag this as a limitation and future direction.
