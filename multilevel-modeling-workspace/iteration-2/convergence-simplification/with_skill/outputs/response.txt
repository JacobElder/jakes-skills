Before writing this up, I'd push back on the model you landed on — there's a real risk it's anti-conservative for your condition test, and a methods section that accurately describes it may draw reviewer scrutiny for exactly that reason. Let me explain the issue and then what to do about it.

## The problem with your current model

Your condition manipulation is **within-subjects** — every subject saw both conditions. That means subjects vary in *how much* they're affected by condition (some people are more sensitive to the manipulation than others). The correct error term for testing a within-subjects effect requires a by-subject random slope for condition.

Your current model `(1 | subject)` only allows subjects to differ in baseline RT. It assumes the condition effect is *identical* across all subjects, which is almost never true. When you drop the slope and use only a random intercept, the residual variance absorbs the between-subject variability in the condition effect — this deflates your standard error and makes the test anti-conservative. Type I error rates in this situation routinely run 2–5× the nominal rate (Barr et al., 2013; Schielzeth & Forstmeier, 2009).

The same question applies to items: does condition vary within items (e.g., a Latin square counterbalancing where each sentence appears in both conditions across subjects)? If yes, `(1 | item)` has the same problem.

## The singular fit doesn't justify dropping the slope

A singular fit warning means the estimated variance for a random effect collapsed to zero or a correlation hit ±1. That's a signal about your data and model — not automatic permission to drop the structure your design requires. Diagnose it first:

```r
library(lme4)
library(lmerTest)

# What you should have tried first:
m_max <- lmer(rt ~ condition + (1 + condition | subject) + (1 + condition | item),
              data = dat, REML = TRUE)
```

If that singular-fits, check *what* is singular before simplifying:

```r
isSingular(m_max)
VarCorr(m_max)   # which variance component is at/near zero?
```

Then work through the convergence decision tree **before** removing theoretically required structure:

### Fix 1 — Try all optimizers

```r
library(allFit)
all_fits <- allFit(m_max)
summary(all_fits)   # do any converge cleanly?
```

Often `bobyqa` or `nloptwrap` with `NLOPT_LN_BOBYQA` converges when the default `nloptwrap` doesn't. If any optimizer gives a clean fit, use that one.

### Fix 2 — Center and scale

Singular fits frequently trace back to predictors that are uncentered or on a scale that makes the optimization landscape poorly conditioned:

```r
# For a binary condition: sum/±0.5 coding helps more than treatment coding
contrasts(dat$condition) <- c(-0.5, 0.5)
```

If RT is in milliseconds, consider log-transforming (RT distributions are right-skewed, and the log scale often gives better-behaved residuals *and* easier optimization).

### Fix 3 — Zero-correlation model as a principled intermediate

If the full correlation structure is the problem (random slope variance is fine but the slope–intercept correlation is hitting ±1), fit a zero-correlation model:

```r
m_zcp <- lmer(rt ~ condition + (1 | subject) + (0 + condition | subject) +
                               (1 | item) + (0 + condition | item),
              data = dat, REML = TRUE)
```

This is theoretically defensible and is the Bates et al. (2015) / Matuschek et al. (2017) recommendation when the full model is overparameterized but the slopes themselves are non-zero.

### Fix 4 — Check if by-item slopes are estimable

If condition does **not** vary within items (i.e., each sentence only appears in one condition — no counterbalancing), then `(1 + condition | item)` is not identifiable and should not be in the model. `(1 | item)` is then correct. But you still need `(1 + condition | subject)`.

## What to include in your write-up — once the model is right

If after all the above you land on a clean model, here's what the random-effects section needs:

**1. The full lme4 formula**, including the random-effects structure spelled out:
> *We fit linear mixed-effects models using lmer (lme4 v1.x; Bates et al., 2015) with REML estimation. The random-effects structure included by-subject random intercepts and random slopes for condition, and by-item random intercepts [and random slopes for condition if applicable].*

**2. Justification for the structure chosen:**
> *This structure was selected as the maximal model justified by the design (Barr et al., 2013), as condition varied within subjects [and within items under counterbalancing].*

**3. If you did simplify, say why and how:**
> *The maximal model produced singular fits attributable to [which component — e.g., the by-item slope variance being near zero]. We simplified by removing [specific component], following the approach of Matuschek et al. (2017). We verified via allFit that convergence was not optimizer-dependent.*

**4. Variance components and ICC:**
Report `VarCorr(model)` output — random-effect SDs, residual SD, and optionally the by-subject ICC. Reviewers increasingly expect this.

**5. Inference method:**
lme4 doesn't print *p*-values by default. If you used `lmerTest`, say "Satterthwaite-approximated degrees of freedom." If you used likelihood-ratio tests, note you refitted with ML (REML = FALSE) for the comparison.

## The short version

**Don't write up `(1 | subject) + (1 | item)` without first trying to recover the random slope for condition.** That model likely has inflated Type I error for your key test, and sophisticated reviewers will flag it. Work through the optimizer sweep and zero-correlation model — 40 subjects × 80 items is a reasonably well-powered design and you may get the slope to converge with the right optimizer or contrast coding.
