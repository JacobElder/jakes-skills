Before you write this up, there's a statistical issue worth flagging — because the random effects structure you landed on may be problematic in a way that affects inference, not just fit.

## The Core Problem

With a **within-subjects condition manipulation**, condition varies *within* each subject, which means subjects likely differ not just in their average RT (intercept) but in *how much* condition affects them (slope). The maximal model for that design is:

```r
lmer(rt ~ condition + (1 + condition | subject) + (1 + condition | item))
```

Your simplified model — `(1 | subject) + (1 | item)` — drops those by-subject and by-item slopes entirely. That's not a conservative choice; it's an **anticonservative** one. By forcing every subject to have the same condition effect, you're removing a source of variance that belongs in the error term for the condition test, which narrows your standard errors and inflates Type I error. This is the exact failure mode Barr et al. (2013) demonstrated in *"Keep it maximal."*

---

## Why Singular Fit ≠ "Drop the Slope"

Singular fits usually have a more specific cause than "the model is overparameterized." The most common culprit is the **intercept–slope correlation** being estimated at ±1.0, not the slope variance itself being zero. That's fixable without dropping the slope:

```r
# Step 1: Decorrelate — remove the correlation parameter, keep the slope
lmer(rt ~ condition + (1 + condition || subject) + (1 + condition || item))
```

The `||` syntax fits intercept and slope as independent, eliminating the correlation parameter. This often resolves singularity while retaining the theoretically necessary slope.

If that still gives warnings, check whether the slope variance itself is near zero using `rePCA()` from lme4 — if a component explains < 0.1% of variance, *then* dropping it is defensible.

---

## Recommended Diagnostic Steps Before Writing Up

```r
library(lme4)

# Fit maximal decorrelated model
m_decor <- lmer(rt ~ condition + (1 + condition || subject) + (1 + condition || item), 
                data = dat, REML = TRUE)
summary(m_decor)
isSingular(m_decor)

# Inspect which components are near-zero
print(rePCA(m_decor), digits = 3)
```

If `m_decor` converges cleanly, use it. If it's still singular, inspect `rePCA()` to see which component is driving it — that tells you exactly what to trim and gives you a principled justification for the write-up.

## What to Include in the Methods (Once You Have the Right Model)

Reviewers and readers need five things:

1. **The maximal model** — state what it was theoretically, even if you didn't use it: *"The maximal model included by-subject and by-item random slopes for condition…"*
2. **The simplification rationale** — *"…which produced singular fit warnings (isSingular = TRUE). We first removed the intercept-slope correlation (using the `||` syntax); [if still singular:] PCA of the random effects (rePCA) indicated that the by-item slope for condition explained < X% of variance, so it was removed."*
3. **The final model formula** — include it verbatim in R syntax, e.g. `rt ~ condition + (1 + condition || subject) + (1 | item)`
4. **Software** — `lme4` version, R version, and whether you used REML for estimation and ML for likelihood-ratio tests (if applicable)
5. **Inference method** — Satterthwaite or Kenward-Roger df approximation (`lmerTest`), or likelihood ratio tests — be explicit

---

## Bottom Line

The model you have right now (`(1 | subject) + (1 | item)`) likely gives you anticonservative *p*-values on condition — a meaningful problem if condition is your primary effect. Try the decorrelated model first; it's almost certainly what you need. That will also give you a much cleaner and more defensible methods section, because you can show you took a principled, stepwise approach rather than stripping out slopes entirely.
