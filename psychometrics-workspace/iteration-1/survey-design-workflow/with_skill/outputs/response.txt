Great setup for a new scale — 8 items, 7-point Likert, N ≈ 600 is genuinely workable for the full EFA → CFA pipeline with this item count. Here is what I'd recommend, and the mistakes that trip up nearly every applied team.

---

## Before you run any statistics: construct definition and cognitive interviews

Before touching the data, make sure you've done two things:

1. **Written down a clear construct definition for "product trust"** — what's in it, and what's explicitly *not* in it (e.g., is "perceived competence" separate from "benevolence"? Is trust about the product itself or the company behind it?). Items written before the construct is bounded tend to produce a scale that measures "vibes about product trust" rather than the construct. This is the number-one mistake in scale development.

2. **Run cognitive interviews on 5–10 people** before your 600-person pilot. Sit with participants, have them think aloud while answering each item, and ask "what did you think that question was asking?" You will find wording problems — double-barreled items, jargon, reference ambiguities — that no item statistic will ever reveal. Skipping this step is penny-wise, pound-foolish.

---

## Sample size: you're in good shape

N = 600 with 8 items is adequate for both EFA and CFA with this scale size. The old "N ≥ 5 per item" or "N ≥ 200" rules are too crude; what actually matters is communality magnitude and factor overdetermination (MacCallum, Widaman, Zhang & Hong, 1999). With 8 items on a single or two-factor trust construct and reasonably strong loadings (h² > .4 on average), 600 gives you stable EFA solutions and comfortable CFA power. Where N matters most is in the CFA split — even with half the sample (n ≈ 300), you're fine for an 8-item one- or two-factor model.

---

## Step 1: EFA on the first half of the sample

**Split your sample before you do anything.** Use ~300 participants for EFA and hold ~300 for CFA. Running EFA on the full dataset and then CFA on the same data is double-dipping — you'll capitalize on chance and then "confirm" exactly what you found. Pre-register the split if you can.

### Use polychoric correlations, not Pearson

Your items are 7-point Likert. Pearson correlations on ordinal items underestimate the true correlation between the underlying continuous traits, which flattens loadings and can produce artifactual factors (an item-difficulty factor where items group by mean endorsement, not content). Use polychoric correlations throughout the EFA.

```r
library(psych)

# Option A: let fa() handle it directly
efa_result <- fa(data_efa,           # ~300-participant split
                 nfactors = 1,        # adjust after parallel analysis
                 fm = "minres",       # minimum residual; robust, no normality assumption
                 rotate = "oblimin",  # oblique — see below
                 cor = "poly")        # polychoric correlations for ordinal data

# Option B: compute polychoric matrix first, then pass it in
pc_matrix <- psych::polychoric(data_efa)$rho
efa_result <- fa(pc_matrix, nfactors = 1, n.obs = nrow(data_efa),
                 fm = "minres", rotate = "oblimin")
```

### Use parallel analysis to determine the number of factors — not eigenvalue > 1

The eigenvalue > 1 (Kaiser) rule reliably overestimates the number of factors. With 8 items, it could easily suggest 2–3 factors where there is only 1. Do not use it as your primary criterion.

Use parallel analysis instead — it compares your observed eigenvalues to eigenvalues from random data of the same dimensions, and you retain only factors whose observed eigenvalue exceeds the random benchmark:

```r
# Parallel analysis — the gold standard for factor count
psych::fa.parallel(data_efa,
                   fa = "fa",      # use FA, not PCA
                   cor = "poly",   # polychoric for Likert
                   n.iter = 500)   # bootstrap iterations for the random baseline
```

Also inspect the scree plot (included in `fa.parallel` output) and check `psych::nfactors()` for Velicer's MAP. Pick the number of factors that is both statistically supported and substantively interpretable — you should be able to name the factor and explain why those items hang together.

### Use oblique rotation (oblimin or promax), not varimax

Varimax forces your factors to be uncorrelated, which is almost never true for psychological constructs — and definitely not for trust-related dimensions (e.g., competence-based and benevolence-based trust would be correlated). Use oblimin or promax. If the factors turn out to be empirically uncorrelated, oblique rotation will tell you that; varimax will *impose* it whether it's true or not.

```r
# oblimin is slightly more thorough; promax is faster — both fine for 8 items
efa_result <- fa(data_efa, nfactors = 1, fm = "minres", rotate = "oblimin", cor = "poly")
print(efa_result$loadings, cutoff = 0)   # inspect pattern matrix — don't suppress loadings
efa_result$Phi                           # factor correlation matrix (oblique solution)
```

## Step 2: Reliability on the EFA sample

Report both **McDonald's omega** and Cronbach's alpha. Alpha is ubiquitous enough that reviewers will expect it, but it assumes tau-equivalence (all items contribute equally to the construct), which is almost never true. Omega is derived from the factor model and doesn't require that assumption — it's the right estimate for a congeneric scale.

For an 8-item scale that's probably unidimensional, omega-total is the key number. If there's a general factor plus subscales, also look at omega-hierarchical (how much variance the general factor alone explains).

```r
# psych::omega() — works directly on raw data, handles polychoric with poly=TRUE
om <- psych::omega(data_efa, nfactors = 1, fm = "minres", poly = TRUE)
om$omega.tot   # omega-total
om$alpha       # alpha for comparison
```

If alpha is, say, .82 but omega is .87, that tells you there's meaningful item heterogeneity — the items aren't equivalent, and alpha was underestimating reliability. Report the difference and explain it.

---

## Step 3: CFA on the holdout half

After EFA tells you the likely factor structure, move to CFA on the held-out ~300 participants. For 7-point Likert items, use the WLSMV estimator in lavaan (treats items as ordered categorical) rather than ML (which assumes continuous normality):

```r
library(lavaan)

model <- '
  product_trust =~ pt1 + pt2 + pt3 + pt4 + pt5 + pt6 + pt7 + pt8
'

fit <- cfa(model,
           data = data_cfa,
           ordered = c("pt1","pt2","pt3","pt4","pt5","pt6","pt7","pt8"),
           estimator = "WLSMV")   # correct for ordinal data; robust chi-square

summary(fit, fit.measures = TRUE, standardized = TRUE)
```

Report CFI, TLI, RMSEA, SRMR — but don't treat Hu & Bentler's (1999) CFI > .95, RMSEA < .06 cutoffs as hard pass/fail thresholds. Those cutoffs came from simulations of continuous normal data and get over-applied. Look at the whole picture: standardized loadings, residual covariances, and interpretability. A CFI of .93 with all loadings above .55 and no large residuals tells a better story than a CFI of .96 achieved by correlated residuals you chased with modification indices.

Compute omega from the fitted CFA model using semTools:

```r
library(semTools)
compRelSEM(fit)   # current preferred call; reliability() is deprecated
```

## Mistakes to avoid — the short list

1. **Eigenvalue > 1 for factor count.** It will tell you that you have 2–3 factors when you have 1. Always use parallel analysis.

2. **Pearson correlations on Likert items.** They bias loadings downward and can manufacture artifactual factors. Use polychoric.

3. **Varimax rotation.** Oblique rotation is strictly more general. If your factors are truly orthogonal, oblique will confirm it.

4. **Reporting only alpha for reliability.** Alpha assumes tau-equivalence; report omega. For an 8-item scale, this is easy with `psych::omega()`.

5. **Running EFA and CFA on the same data.** Split your sample. This is not optional if you want the CFA to be confirmatory.

6. **Skipping cognitive interviews.** No amount of Cronbach's alpha will tell you that item 4 was ambiguous. Talk to 5–10 real users before your pilot.

7. **Writing items before defining the construct.** Know what "product trust" is — and isn't — before writing items.

---

## Suggested analysis sequence

1. Cognitive interviews (5–10 people) → revise items if needed
2. Random 50/50 split of 600 participants (or 60/40 toward EFA if you want more stability)
3. EFA half: polychoric correlations, parallel analysis for factor count, oblimin rotation, omega + alpha reliability
4. CFA half: lavaan with WLSMV, report fit indices + standardized loadings + omega via compRelSEM()
5. External validity: correlate the scale score with theoretically related constructs (e.g., purchase intent, brand attitude) to build your nomological network
6. If you compare groups later, test measurement invariance before interpreting group mean differences

With 600 participants and 8 items, you have everything you need to do this right.
