For EFA on 25 Likert items in R, here is a sensible, defensible default call and the reasoning behind each argument.

## Step 0: Determine the number of factors first

Do not guess the number of factors or use Kaiser's eigenvalue > 1 rule (it overextracts, often badly). Run parallel analysis first:

```r
library(psych)

# fa = "fa" uses the factor model, not PCA — this matters
fa.parallel(your_data, fa = "fa", cor = "poly")
```

The `cor = "poly"` argument tells `fa.parallel()` to use polychoric correlations, consistent with what you'll use in the actual EFA. Parallel analysis compares your observed eigenvalues to eigenvalues from random data of the same dimensions; retain factors whose observed eigenvalue exceeds the random (or 95th percentile) benchmark. Look at the scree plot alongside the output. Also consider `psych::nfactors()` for Velicer's MAP as a cross-check.

Pick a candidate number of factors — call it k — and then fit k−1, k, and k+1 models and compare loading patterns and interpretability.

## Step 1: The EFA call

```r
library(psych)

efa_result <- fa(
  your_data,
  nfactors = k,          # determined by parallel analysis above
  fm = "minres",         # minimum residual: doesn't require normality, handles
                         # ordinal data well, less prone to Heywood cases than ML
  rotate = "oblimin",    # oblique rotation: psychological constructs are correlated;
                         # varimax imposes orthogonality that is almost never true
  cor = "poly"           # polychoric correlations: Likert items are ordinal discretizations
                         # of underlying continuous traits; Pearson underestimates
                         # correlations and biases loadings downward
)

print(efa_result, cut = 0.3, sort = TRUE)  # pattern matrix; sort items by factor
```

## Why each argument matters

**`cor = "poly"` — polychoric correlations**
Likert items with 5 or fewer response options are ordinal, not continuous. When you compute Pearson correlations on them, you underestimate the true underlying correlation between traits (because the discretization attenuates). Polychoric correlations model item responses as discretizations of latent continuous variables and estimate the correlation between those latent variables. This produces higher, less-biased loadings and avoids the artifactual "difficulty factor" that can appear in Pearson-based EFAs (where items separate by endorsement frequency rather than content).

**`fm = "minres"` — minimum residual extraction**
`minres` is the default in `psych::fa()` for good reason: it minimizes the off-diagonal residuals of the factor model, doesn't require multivariate normality, and is less prone to Heywood cases (communality > 1) than maximum likelihood. It's the safest general-purpose choice for Likert data. If you want a chi-square test of model fit and standard errors, switch to `fm = "ml"` — but this requires multivariate normality and can be fragile with sparse ordinal data.

**`rotate = "oblimin"` — oblique rotation**
Oblique rotation (oblimin, promax) allows factors to correlate; orthogonal rotation (varimax) forces factors to be uncorrelated. For psychological constructs, oblique is almost always the right choice — constructs like "anxiety" and "depression" are correlated in nature, and imposing orthogonality is a false structural constraint that distorts your loading pattern. If your factors turn out to be empirically near-zero correlated, oblique gives you the same answer as orthogonal anyway. Promax is an alternative oblique rotation that is faster; oblimin gives somewhat more control. Either is defensible.

Do NOT use varimax as a default for Likert-based psychological scales.

## What to examine in the output

```r
# Pattern matrix (use this for interpretation — standardized regression weights)
efa_result$loadings

# Factor correlations (because you used oblique rotation)
efa_result$Phi

# Communalities (h²): low values (<.30) flag items that aren't well captured
efa_result$communalities

# Complexity: items with complexity > 1.5 are cross-loading substantially
efa_result$complexity
```

For oblique solutions, always report the pattern matrix (not the structure matrix) when naming and interpreting factors. Report factor correlations — if reviewers ask "why oblique?", the factor correlation matrix is your evidence.

## Reporting checklist (minimum)

- Correlation type: polychoric
- Extraction method: minres (or ML)
- Number of factors and how determined: parallel analysis + scree + interpretability
- Rotation: oblimin (oblique)
- Pattern matrix with all loadings
- Factor correlation matrix
- Communalities
- KMO ≥ .60 check (preferably ≥ .80) and Bartlett's test of sphericity

## One caveat on sample size

25 items across k factors: make sure you have adequate N. The old "N ≥ 200" rule is too crude. What matters is communality magnitude and overdetermination (≥ 4 items per factor). With strong factors (average h² > .6), N = 150 can be sufficient; with weak factors, even N = 400 may not give stable rotations. If N is borderline, run `psych::fa.bootstrap()` to assess solution stability.
